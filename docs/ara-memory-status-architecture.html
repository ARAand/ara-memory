26시간째 제작 중

Ara Memory OS 현재 작업 상황과 아키텍처

목표는 “전체 프롬프트와 파일을 매번 다시 읽는 기억”이 아니라, 원문은 로컬에 안전하게 보존하고 Codex가 필요한 순간에는 목적, 정체성, 실패, 증거, 오래된 단서만 압축해서 불러오는 자연스러운 기억 구조다.

현재 브랜치codex/ara-memory-natural-memory-gates
최근 완료global spreading sandbox
이번 단계privacy pre-push gate
전체 상태구현 중, 공개 안전성 강화

완료된 축

  • 로컬 우선 저장소: ledger, SQLite, FTS, capsule 계층.
  • always-on ingress: remember-turn, spool-turn, drain-spool.
  • worker loop: 백그라운드 정리, 리뷰, 회귀, 백업 검증.
  • hot/cold/lifecycle: 핵심 기억과 오래된 증거를 분리.
  • goal-roadmap: 목적 기반 자기 진단판.
  • global spreading sandbox: 전역 그래프 확산을 읽기 전용으로 시험.

지금 붙인 축

  • privacy-pre-push CLI가 tracked/staged 파일을 검사.
  • 사적 메모리 루트, DB, ledger, archive, log, backup 파일을 fail 처리.
  • hidden reasoning marker와 실제 secret-like text를 공개 전 차단.
  • 테스트/문서 fixture의 가짜 키는 warning으로 남겨 회귀 테스트를 보존.
  • goal-roadmap에 공개 전 privacy gate 항목을 포함.

현재 리스크

  • health는 cold/backup pressure 때문에 watch가 남을 수 있다.
  • 그래프 확산은 아직 sandbox라 실제 recall 기본값으로 켜면 안 된다.
  • 사람 같은 기억은 보상 점수 최적화가 아니라 목적성, 망각, 회상 실패 기록이 같이 필요하다.
  • public repo와 local memory root의 경계는 계속 자동 검사해야 한다.

아키텍처

1. Capture프롬프트, assistant 요약, 파일, 이미지, 명령, 결정 사항을 turn envelope로 수집한다.
2. Guardpre-retain privacy guard가 secret, direct identifier, hidden reasoning을 저장 전에 redaction한다.
3. Store원문 증거는 로컬 ledger/archive에 남기고, 검색용 capsule과 관계 그래프를 분리한다.
4. Consolidateworker가 episode, candidate, stable, cold memory를 정리하고 회귀 테스트를 돌린다.
5. RecallCodex는 전체 원문 대신 hot memory, recall policy, cold-map 단서, 증거 링크만 예산 안에서 받는다.

8-16h

다음 판단

다음 24시간의 핵심은 기능 추가가 아니라 “기억의 목적성”을 고정하는 것이다. 모든 원문을 저장하는 것은 쉽지만, 자연스러운 기억은 무엇을 잊고 무엇을 다시 떠올릴지 결정하는 구조에서 나온다.

  • 우선 공개 안전성 gate 완료 후 push.
  • 다음 재맥락화/재고착 프레임 구현.
  • 그 다음 memory worker와 recall controller를 분리 검증.
이 문서는 현재 작업 상태를 사람이 빠르게 판단하기 위한 정적 HTML 상태판이다. private memory 원문, archive object 본문, 사용자 프롬프트 원문은 포함하지 않는다.
