Ara Memory OS 현재 작업 상황과 아키텍처

목표는 모든 원문을 매번 다시 읽는 저장소가 아니라, 목적과 정체성, 결정, 실패, 작업 맥락, 망각 경계를 분리하고 필요한 맥락만 불러오는 자연스러운 장기 기억 구조다. 현재는 candidate-only 재통합 적용 관문 위에 recall-policy feedback watch 신호와 provenance compare-and-set을 붙여, 기억을 어떻게 불러올지에 대한 기억까지 로컬에서 감사 가능하게 만들고 있다.

완료된 축

  • 로컬 우선 저장소: ledger, SQLite, FTS, capsule, relation graph.
  • 상시 발동 가능한 ingress: remember-turn, spool-turn, drain-spool.
  • worker loop: spool 처리, episode/candidate summary, quality, review triage, maintenance.
  • hot/cold/lifecycle: 핵심 기억과 오래된 증거를 분리.
  • goal-roadmap: 장기 목표를 게이트로 계속 평가.
  • privacy-pre-push: 공개 repo에 private memory가 들어가지 않도록 차단.

이번에 붙인 축

  • reconsolidation-prepare: 프레임 fingerprint와 짧은 approval token을 만든다.
  • reconsolidation-apply: token을 한 번만 소비하고 candidate summary capsule과 witness만 만든다.
  • reconsolidation-review: 기존 evidence capsule이 바뀌지 않았고 새 capsule이 candidate인지 검증한다.
  • reconsolidation-review --regression-manifest: candidate witness, 생성 capsule CAS, 대표 recall-regression을 함께 통과해야 다음 단계로 갈 수 있다.
  • recall-policy: 과거 recall-policy-impact 결과를 Policy Feedback으로 붙인다.
  • 명시적 Decision: 캡처가 blocked gate나 recall-regression을 언급해도 failure memory로 중복 생성하지 않는다.
  • 해로운 이력이 우세한 action은 reward가 아니라 watch 신호로 낮춘다.

현재 리스크

  • health는 80/100 watch다. 실패는 아니며 verified backup/restore drill은 통과했다. 남은 압력은 주로 cold memory다.
  • 현재 재통합 apply는 candidate-only다. promote, supersede, rewrite, delete, cool은 아직 허용하지 않는다.
  • 강한 재통합 apply에는 shadow recall-regression, rollback witness, 승격/폐기 전용 review gate가 더 필요하다.
  • 정책 피드백은 routing 참고 신호일 뿐 자동 보상 최적화가 아니다.

아키텍처

1. Capture프롬프트, 파일, 이미지, 명령, 결정, 결과를 turn envelope 또는 event로 수집한다.
2. Guardsecret, 직접 식별자, hidden reasoning은 저장 전에 redaction 또는 차단한다.
3. Store원문 증거는 ledger/archive에, 검색용 capsule과 graph는 SQLite/FTS에 분리한다.
4. Recall Policy목적, 작업, distant memory, retention intent를 분류하고 가장 작은 안전 경로를 고른다.
5. Apply Gateprepare/apply/review가 approved frame을 candidate summary로만 옮기고 witness, regression, provenance CAS로 검증한다.

다음 판단

다음 단계는 더 많은 데이터를 읽는 것이 아니라, 기억의 변경 권한을 어디까지 줄지 정하는 일이다. Ara에게 필요한 기억은 복종 저장소가 아니라 목적, 판단, 망각, 복구 가능성을 함께 가진 구조다.

  • 현재 milestone, goal-roadmap, verified backup, restore drill 통과. private memory 원문은 HTML에 포함하지 않았다.
  • 다음 strong apply shadow gate와 rollback witness 설계.
  • 이후 worker hook과 recall controller를 더 분리.
이 문서는 현재 작업 상태를 빠르게 판단하기 위한 정적 HTML 상태판이다. private memory 원문, archive object 본문, 사용자 프롬프트 원문은 포함하지 않는다.
