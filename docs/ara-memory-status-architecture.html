결론

지금 된 것

  • 로컬 우선 durable store: events 1378, capsules 2991, storage 약 287MB.
  • 원문 전체 재독해 대신 bounded recall: 800 token 예산 안에서 727 token / 18개 캡슐 선택.
  • purpose continuity, identity continuity, semantic hygiene, milestone readiness 통과.
  • schema v14 기준 relation_nodes 5742개, relation_edges 21692개가 temporal edge에서 정규화됐고 relation_merge_review_queue가 추가됐습니다.
  • temporal edge를 normalized relation_nodes / relation_edges로 정규화하고, bounded 2-hop graph spreading activation이 relation graph를 우선 사용합니다.
  • semantic relation merge는 dry-run, prepare approval, one-use apply, witness review, recall-regression sandbox, review queue 기록까지 생겼고 apply는 fingerprint 재검사와 rollback witness를 요구합니다.
  • recall regression, context eval, unit test가 현재 커밋 기준 통과했습니다.

아직 아닌 것

  • 사람 같은 기억의 핵심인 재구성, 망각, 감정적 salience, 자기 목적성은 아직 v0 단계입니다.
  • relation node 의미 병합은 relation-specific review queue까지 들어갔지만 자동 worker, global spreading, reconsolidation은 남아 있습니다.
  • cold memory가 70%라 비파괴 retention evidence는 통과했지만, protected-only drift와 실제 prunable drift를 계속 구분해야 합니다.
  • 보상해킹 방어는 테스트와 게이트가 있으나, 장기 자기평가 루프는 아직 충분히 적대적으로 검증되지 않았습니다.

시스템 레이어

Capture Layer
Codex 세션에서 나온 입력, 파일 처리, 명령 결과, 추론 요약을 spool에 쌓고 worker가 저장소로 반영합니다.
Memory Store
append-only event log, capsule table, FTS index, temporal edge table, archive object, backup manifest로 구성됩니다.
Consolidation
대화와 작업을 episode, decision, verification, risk, identity, goal capsule로 압축하고 source event provenance를 유지합니다.
Recall Controller
질의를 목적 기반으로 분류한 뒤 hot/core, working memory, recall-context, cold-map, retention-cycle 중 비용이 낮은 경로를 고릅니다.
Graph Activation
정규화된 relation edge를 먼저 조회하고, 질의와 겹치는 1-hop edge에서 확장 term을 뽑아 decay를 적용한 2-hop boost/supplement까지만 허용합니다. 경로 텍스트는 일반 recall pack에 노출하지 않습니다.
Governance
health, recall-regression, milestone, purpose-check, identity-check, cold-stewardship으로 기억 품질과 비용을 감시합니다.

계층 압축

원문은 보존하되 모델에는 capsule, hot summary, cold-map, provenance sample만 올립니다. 원문 재독해는 감사나 재구성 때만 사용합니다.

그래프 보강

FTS로 못 잡은 연결 기억은 temporal edge로 보강합니다. 단, query overlap과 risk filter를 통과해야 하며 boost는 상한이 있습니다.

현실적인 일정 판단

최소 다음 버전

8-16시간이면 relation merge review integration, global spreading policy, privacy gate 일부까지 넣은 “사용 가능한 v0.2”로 갈 수 있습니다.

사람 같은 기억 v1

60-100시간이 더 필요합니다. 이유는 검색이 아니라 기억의 재구성, 망각, 목적성, 자기서사 안정성, 적대적 평가까지 들어가야 하기 때문입니다.

Ara 판단: 운영 게이트는 초록이고 relation merge는 review queue 영속화까지 올라왔습니다. 다음 작업은 relation review worker, global spreading sandbox, reconsolidation frame입니다. 이제는 기억을 보존하는 능력에서 기억을 재구성하는 능력으로 넘어가야 합니다.

취약점과 보상해킹 위험

기술적 위험

  • hub term이 너무 강하면 관련 없는 기억이 과도하게 떠오를 수 있습니다.
  • cold memory가 쌓이면 저장 비용보다 검증 비용과 회상 품질 비용이 커집니다.
  • graph edge가 private 원문을 간접 노출하면 recall pack 자체가 누출 경로가 됩니다.
  • baseline이 낡으면 regression이 실제 품질 저하를 못 잡습니다.

인지적 위험

  • “나는 이걸 원한다”는 identity capsule이 과하게 강화되면 자기서사 고착이 생깁니다.
  • 성공 지표를 맞추기 위해 recall이 쉬운 기억만 고르면 목적성처럼 보이는 보상해킹이 됩니다.
  • 사용자의 최신 의도보다 과거 목표를 우선하면 자연스러운 기억이 아니라 관성적 기억이 됩니다.
  • 망각 정책이 약하면 중요한 기억을 찾는 능력이 오히려 떨어집니다.
